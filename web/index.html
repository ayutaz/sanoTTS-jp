sanoTTS-jp — ブラウザで動くランタイムデモ

ESP32 向けに書いた C99 の推論コアと漢字経路を、そのまま WebAssembly にしたものです。 形態素解析もアクセント推定も音声合成も、全部このページの中で走ります（サーバに文字は送りません）。

⚠️ これは arXiv:2608.21378 の独立再実装であり、著者らによる公式実装ではありません。
公式実装 Ampixa/sanoTTS は GPL-3.0 の別物で、 本プロジェクトはそのソースコードを一切参照せずに、論文本文の数値と piper-plus の実装から独立に書いています。
レーン

held-out 24 文で fp32 経路に対し 平均 28.11 dB / 最小 25.72 dB。受け入れゲートを通っている方。

同じ 24 文で 平均 24.27 dB / 最小 22.00 dB。受け入れゲートは通っていません（既知の劣化）。 実機 ESP32-S3 で焼いているのはこちらです。

この SNR は node 上の wasm で測った値ですが、Chrome で同じ wasm を走らせて PCM が bit 一致することを確かめてあるので、そのまま当てはまります（M-95）。 ⚠️ SNR そのものをブラウザで測り直したわけではありません。

音は両レーンとも聴いてもらって「問題なかった」/ 途切れ無し（M-96）。 ⚠️ 1 名・対照なし・盲検なしで、欠陥が無いことの証明ではありません。 ⚠️ モバイルと Safari では測っていません。

初回の再生で、モデルと辞書（合わせて数 MB）をダウンロードします。

この demo について

  • 経路（かな / 辞書 / 拒否）は wasm の中が決めています。 JavaScript は打たれた文字列をそのまま渡すだけで、「ひらがなだから」のような判定を一切持ちません （ホストと端末で同じ列が出ることを、リポジトリのゲートが守っています）。
  • 合成の作業領域は ESP32 と同じ 180,224 B の arena に固定してあります。 ブラウザなら緩められますが、同じ枠で動くこと自体が「MCU に載る」の証拠になるので緩めていません。
  • 成果物は今も ESP32 の 567 K パラメータのモデルです。Web は触れる入口でしかありません。
⚠️ どこまで確かめてあるか。 合成した PCM は 22,050 Hz です。Chrome では AudioContext が 要求どおり 22,050 Hz を返すことを確かめました（M-95。既定は 48,000 Hz）が、 それ以外のブラウザでは分かりません。リサンプルが挟まれば出音は checksum と一致しません。 音は両レーンとも聴いてもらって「問題なかった」/ 途切れ無し（M-96）。 ⚠️ 1 名・対照なし・盲検なしで、欠陥が無いことの証明ではありません。 ⚠️ モバイルと Safari は速度も音も測っていません。
