# K-1 実装計画 — 端末で漢字・カタカナを扱う

作成 2026-08-31 / 前提調査 [`../research/k1-kanji-katakana-ondevice.md`](../research/k1-kanji-katakana-ondevice.md)

**本計画は既存の [`phase0-1-implementation-plan.md`](phase0-1-implementation-plan.md) とは別トラック**。
あちらは「かな中間表現の生徒モデル」を実機で動かす話で、残りは実機のサイクル実測だけ。
こちらは**入力境界を漢字かな交じり文まで戻す**話で、成立すればホスト G2P が不要になる。

⚠️ **本計画は「実現可能」という調査結果に乗っているが、実機で 1 度も動かしていない。**
K-1 調査の一致率はすべて「OpenJTalk と同じ出力か」であって正しさではなく、**聴取はゼロ**。

---

## 0. 調査で既に済んでいること（やり直さない）

| 項目 | 結果 | 出所 |
|---|---|---|
| 辞書は mmap されるか | **される。98.4 MB マップ / 常駐 1,040 KB** | K-1 §4-1 |
| TTS 専用バイナリのサイズ | **1 エントリ 28.29 B**（MeCab 形式の 130 B に対し 4.6 分の 1） | K-1 §2-2 |
| 形式が解析器を駆動できるか | **held-out 全 2,333 文で 2,151/2,151 = 100.00%** | K-1 §3 |
| アクセント天井の正体 | **公開フラグを持たない 4 段 = 126 行。外部定数は 76 件のかな表のみ** | K-1 §5 |
| Viterbi / matrix.bin を落とせるか | **落とせない**（貪欲はアクセント 15.52%）。**縮むのは可** | K-1 §6-6 |
| 1 文あたりヒープ | **ピーク約 251,504 B**。支配項はラベル固定バッファ（86%） | K-1 §4 |
| カタカナのコスト | **端末テーブル 0 B** | K-1 §8 |

**設計として確定したもの**（調査で測って決まった。実装で再検討しない）:

- trie の鍵は **文字 ID（idvar）**。**path 圧縮は入れない**（アルファベットを詰めた後は純損）
- **`pron` の dedup はしない**（ポインタ代で純損）。潰すのは **orig / read の例外**
- matrix.bin は **int8 行ごとスケール**（3.79 MB → 1.90 MB、アクセント句 99.74%）
- 値プールのオフセット チェックポイントは **32 間隔**
- **nbest は使わない**（Path が max 147,456 B 増える）

## 1. 最初に決めること — 動作点

**この選択が後段のすべてを縛る。K-0 で凍結する。**

| | 16 MB (N16R8) | 32 MB (N32R16V) |
|---|---|---|
| エントリ数 | 263,000 | 788,923（フル） |
| 辞書イメージ | 約 10.3 MB | 24.68 MiB（最適化後 15.38 MiB は算術） |
| 音素列一致 | 91.31% | 100% |
| アクセント一致 | 81.55% | 100% |
| 実質の体感 | **1 文に 1 回くらいアクセントがずれる** | **ほぼ教師と同等**（読みが違うのは 0.6% の文） |
| MMU 窓 | 余裕 | **⚠️ 未確認。次のブロッカー候補** |
| 調達 | 現行品 | **1.8 V octal のみ。脆い**（B-0 §5） |

**推奨は 16 MB で始めること。** 32 MB は MMU 窓の実測が取れてから。
16 MB で成立させておけば、32 MB はエントリ数を増やすだけで届く。

## 2. フェーズ

### K-0 前提の凍結とブロッカー潰し

**目的**: 後段が全部依存する 3 つを固定し、**唯一残っている未知のブロッカーを先に潰す**。

**ゴール**:

1. **ボードと動作点が凍結されている**（§1 の表から 1 行を選び、決定記録に残す）
2. **辞書リビジョンが凍結されている。** ⚠️ このマシンには `sys.dic` が **4 種類**ある
   （103,073,776 / 103,082,017 / 103,094,645 / 103,131,410 B）。**どれを正とするかを決め、
   SHA-256 を manifest に固定する。** 教師のラベル生成経路が引くのは pyopenjtalk 同梱版
   （789,388 entries）で、B-0 が測定に使ったのは piper-plus 側（788,923）。**両者は別物。**
3. **ESP32-S3 のデータ mmap 窓に選んだ辞書が入ることが、データシートか実機で確認されている**

**受け入れ条件**: 上の 3 つが `docs/decisions.md` に D-番号で記録され、
辞書の SHA-256 が manifest にある。

**リスク**: 3 が否定されたら 32 MB 案は消える（16 MB 案は影響なし）。

### K-1 ホスト側エンコーダ

**目的**: NAIST-JDIC → TTS 専用バイナリの変換器を、リポジトリに再現可能な形で置く。

**ゴール**: 選んだ動作点のエントリ集合が 1 本のバイナリになり、**全エントリを復元して
元の 11 フィールドと一致する**。

**受け入れ条件**（すべて陰性対照つき）:

| # | 条件 |
|---|---|
| G1 | 全エントリで 11 フィールド往復一致（調査では 788,923/788,923） |
| G2 | 陰性対照: レコードを 1 バイト壊すと G1 が落ちる |
| G3 | LOUDS の common-prefix-search が総当り参照と一致。**ヒット数を併記し、2 文字以上のヒットが十分あること**を示す |
| G4 | 陰性対照: **実際にヒットした経路上の**ラベルを壊すと G3 が落ちる |
| G5 | チェックポイントからのオフセット復元が materialise 版と一致 |

⚠️ **G3 は調査で 1 度空虚になった** — ランダム 3,000 語で組んだらヒットが 12,546 位置中
**17 件**しか出ず、「一致」の中身がほぼ全部「両方とも空を返した」だった。
⚠️ **G4 も 1 度空虚になった** — テスト文に現れないノードを壊しても不一致 0 になる。

**依拠する実測**: K-1 §2。**posid は (lc, rc, 品詞6つ組) から一意に決まる**ので保存不要、
`compound` 欄は全件 0、同綴りエントリは token 配列上 100% 連続。

---

### K-2 C リーダ + Viterbi

**目的**: 端末側で辞書を引き、形態素解析する。

**ゴール**: **ホストの MeCab と held-out 全数で分割・読み・アクセントが一致する。**

**受け入れ条件**:

| # | 条件 |
|---|---|
| G6 | held-out 全 2,333 文で MeCab と分割・`pron`・(acc, chain) が一致（未知語を含む文を除く） |
| G7 | 陰性対照: 接続コストを 0 にすると G6 が落ちる |
| G8 | `cc -Wall -Wextra` で警告 0、malloc をコアで呼ばない（arena を渡す。既存 C99 コアと同じ規約） |

**依拠する実測**: K-1 §3 でホスト実装が 2,151/2,151 = 100.00% を達成済み。**同じ突き合わせを C で再現する。**

⚠️ **実装で必ず踏む落とし穴**（調査で全部踏んだ。K-1 §9-3 / §9-4）:

- **matrix.bin の索引は MeCab 本家の式では合わない。** 正しくは
  `flat[rc_prev + 1377 * lc_cur]`（本家の `lcAttr + lsize*rcAttr` は一致 0.91%）
- **LOUDS の子ノード番号は `rank1[p]`**（`rank1[p+1]` ではない）。誤ると
  **落ちずに「全部 1 文字に分割される」**
- **位置ごとに 1 本だけ最良経路を残すのは Viterbi ではない。** ノードごとに前任を持つ
- `link_cost` は `word_cost` を含む。生の遷移コストと比べると**陰性対照が壊れる**

### K-3 未知語ノード生成

**目的**: 辞書に無い語で経路が途切れないようにする。

**ゴール**: **経路を張れない文が 0 件**になる。

**受け入れ条件**:

| # | 条件 |
|---|---|
| G9 | held-out 全数で経路なしが 0 件（調査のホスト実装では 104 文 = 4.5% が張れなかった） |
| G10 | 未知語を含む 78 文で MeCab と出力が一致 |
| G11 | 陽性対照: 幽霊漢字（彁 / 妛 / 椦）で**意図どおり脱落する**ことを確認 |

**依拠する実測**: 未知語は held-out 全数で **83 / 38,269 token = 0.22%**、**78 文 = 3.34%**。
中身は**ほぼカタカナの外国固有名詞の断片**（`ーヌ` `ーヴァ` `ーリャ`）と単漢字。
`unk.dic` の feature は **7 列しかなく `read` / `pron` / `acc` / `chain` を持たない**
（これが「無音で消える」の正体）。

⚠️ **未知語は誤読ではなく無音で消える。** 音では気づけないので、**脱落文字数を数えるゲート**
を必ず置くこと。

---

### K-4 アクセント規則の C 移植 ← **新規性の中核**

**目的**: 「C 実装だけではアクセントが 76% で頭打ち」という制約を外す。

**ゴール**: **既定経路とアクセントが 100.00% 一致する。**

**移植対象は 4 関数・126 行**（すべて NJD ノード列だけを見る純関数）:

| 段 | 実質行数 | 外部定数 | LOO 不一致文数 |
|---|---:|---|---:|
| `retreat_acc_nuc` | 36 | **なし** | **214** |
| `modify_acc_after_chaining` | 42 | **なし** | **204** |
| `modify_filler_accent` | 21 | なし | 84 |
| `suppress_u_long` | 27 | `_DAN_MAP` 76 件（かな表） | 0 |

**受け入れ条件**:

| # | 条件 |
|---|---|
| G12 | held-out 全数で、既定経路とアクセント（chain_flag 連結の句列）が一致 |
| G13 | 陰性対照: 4 段のうち 1 段を抜くと G12 が落ちる（各段について） |

**依拠する実測**: K-1 §5。**語彙 2 段を切ってもアクセントは 100.00% 一致する**
（SudachiDict 217 MB と nani ONNX の寄与は合計 0.13pt）。参照実装は `g2p_pure4.py`。

⚠️ `process_odori_features` は**移植しない**（`jtalk.run_frontend()` に再入する不純な段で、
寄与は 0 文）。

⚠️ **読みの差 0.60% は残る。** これは語彙側（SudachiDict）なので安くは直らない。
ただし**ラベル生成を端末と同じ設定に揃えれば定義上消える**（K-6 の判断事項）。

---

### K-5 メモリの詰め

**目的**: 1 文あたりのピーク RAM を予算内に収める。

**ゴール**: **1 文ピークが実測で 150 KB 以下**（TTS 本体 197 KB と合わせて SRAM 512 KB に
十分な余裕を残す）。

**受け入れ条件**:

| # | 条件 |
|---|---|
| G14 | 最長文でのヒープ + スタックのピークが実測されている（**スタックは調査で未計測**） |
| G15 | ラベルバッファの固定長を詰めてある |
| G16 | 陰性対照: 詰める前後で出力が bit 一致 |

**依拠する実測**: 1 文ピーク **約 251,504 B**、うち **86%（216,064 B）が
`jpcommon_label.c:668` の `calloc(MAXBUFLEN=1024)`**（実ラベルは 180 字前後）。
**1024 → 256 B にすれば約 90 KB に落ちる。**
ラティスは `mecab_node_t` 72 B（ESP32-S3 クロスコンパイル実測）× max 681、
FreeList 粒度（512 ノード単位、`free()` は返さない）込みで 73,728 B。

### K-6 ホストとの一致 + ラベル方針の決定

**目的**: 端末が出す音素列が、生徒が学習した入力と一致することを保証する。

**ゴール**: **漢字文 → 端末 G2P → 音素ID列** が、**ホスト経路と同じ列**になる。

**受け入れ条件**:

| # | 条件 |
|---|---|
| G17 | held-out 全数で端末経路とホスト経路の音素ID列が一致 |
| G18 | 既存の入力仕様（かな中間表現）が**壊れていない**（`make -C csrc all-test` が通る） |

**ここで判断が要る**: 読みの差 0.60% を
**(a) 許容する**か、**(b) ラベルを端末と同じ設定で再生成する**か。
(b) なら差は定義上消えるが、**ラベル再生成（CPU 40 分）+ 再学習（MPS 1.3 時間）**が要り、
hook が本番パックの再生成を deny するので D-015 の扱いを決める必要がある。

---

### K-7 ESP32 ビルドと QEMU

**目的**: 実機に持っていく前に、載ることと動くことを確かめる。

**ゴール**: **QEMU で漢字文から合成まで完走する。**

**受け入れ条件**:

| # | 条件 |
|---|---|
| G19 | `idf.py build` が通り、app 枠と辞書パーティションに収まる |
| G20 | QEMU で漢字文を 1 行入力して合成が完走する |
| G21 | **同じターゲット上の 2 構成**（辞書あり / かな入力）で既存経路の出力が bit 一致 |

⚠️ **ホストとターゲットは bit 一致しない。それは正常**（float の丸めが違う）。
**bit 一致を主張してよいのは同じターゲット上の 2 構成を比べたときだけ。**

---

### K-8 実機

**目的**: 唯一測れていないものを測る。

**ゴール**: **1 文あたりの G2P レイテンシがサイクル実測で出ている。**

**受け入れ条件**: G2P が発話長に対して十分小さい（目安 1% 未満）ことが実測で示される。

⚠️ **ボードが無い。** これは既存計画の D-3d と同じ待ちで、K-1 固有の障害ではない。

## 3. 主要リスク

| リスク | 影響 | 状態 |
|---|---|---|
| **ESP32-S3 の mmap 窓にフル辞書が入らない** | 32 MB 案が消える | ⚠️ **未確認。次のブロッカー候補**（K-0 で潰す）。16 MB 案は影響なし |
| **実機が無い** | レイテンシが測れない | ⚠️ 既存計画 D-3d と同じ待ち |
| **スタック使用量が未計測** | K-5 のゴールが立たない | ⚠️ `jpcommon_label.c` 等がフレームに `char buff[1024]` を持つ |
| **OpenJTalk C 本体のコードサイズ** | app 枠に入らない可能性 | ⚠️ **xtensa ビルド未実施**。B-0 の時点から未測定のまま |
| 126 行の移植忠実度 | アクセントが戻らない | ⚠️ 未検証。**G12 / G13 で潰す** |
| **一致 ≠ 正しさ** | 「教師と同じ」だが日本語として正しいかは別 | ⚠️ ネイティブ正解データが存在しない。**聴取ゼロ** |
| 未知語がカタカナ外国名に集中 | 固有名詞の多い文で脱落 | ⚠️ 0.22% token / 3.34% 文。**ドメイン外プローブが 31 文しかない** |
| ヒープ実測が macOS の malloc | ESP32 に持ち越せない | ⚠️ 持ち越せるのは `sizeof` のクロスコンパイル値だけ |
| 辞書リビジョンの取り違え | 測定が別物になる | ⚠️ **4 種類ある。** K-0 で凍結する |

## 4. 測っていないこと

- **実機で 1 度も動かしていない。** 速度は誰も測っていない
- **聴取ゼロ。** 核位置が 4 モーラずれる 47 件が可聴かは不明
- **枝刈り水準での精度は新形式で測り直していない**（フル辞書での転移は構成的に成立）
- **LOUDS と darts のページ数比較は未成立**（3 者が別々の領域を数えていた。K-1 §4-2）
- **合成した最適化イメージ（15.38 MiB）は算術**。まとめてビルドしていない
- **外部の先行事例（AquesTalk 等）は未調査**（調査時に WebSearch が拒否された）

---

## 5. やらないこと

- **貪欲最長一致で Viterbi を置き換える**（アクセント 15.52% で使い物にならない）
- **path 圧縮**（文字 ID 鍵の後は純損）
- **`pron` の dedup**（ポインタ代で純損）
- **nbest API**（Path が max 147,456 B 増える）
- **`process_odori_features` の移植**（不純・寄与 0）
- **かな中間表現の入力仕様を捨てる**（K-6 G18 で守る。漢字対応は**追加**であって置換ではない）
