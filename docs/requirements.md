# sanoTTS-jp 要件定義書

- 版: 0.1（2026-08-26）
- 対象: arXiv:2608.21378 "sanoTTS" の蒸留レシピを日本語に適用し、**ESP32 上で動く日本語 TTS** を作る
- 位置づけ: 検証 (PoC)。生成物は配布しない
- 数値の一次ソース: [`measurements.md`](measurements.md) / 決定の経緯: [`decisions.md`](decisions.md)

本書の数値は**すべて実測**である。未測定の項目は「未測定」と明記する。

---

## 1. 背景と目的

### 1.1 なぜ作るのか

論文 sanoTTS は、567,008 パラメータの TTS を ESP32-S3 上で **0.22× リアルタイム**で動かした。
英語・ベトナム語・インドネシア語で実証されているが、**日本語版は存在しない**。

piper-plus はブラウザ (WebAssembly) では既に日本語 TTS を実現している。
したがって本プロジェクトの価値は **ESP32 で動くこと**にのみある。
ブラウザ向けの再実装には価値がない。

### 1.2 何が障壁だったか

日本語 G2P（OpenJTalk + NAIST-JDIC）は **102 MB** で ESP32 に載らない。
実測の結果、枝刈りでも解決しないことが分かった:

| 辞書サイズ | 文単位の音素列一致率 |
|---:|---:|
| 11.57 MB（16 MB ボードに載る最大） | 73.0% |
| 40.05 MiB | 95.5%（**32 MB ボードにも入らない**） |

さらに教師の G2P は Python 後処理層（SudachiDict 207 MB）に依存しており、
C 実装のみに落とすと**辞書サイズと無関係に**アクセントが 16〜24% ずれる。

### 1.3 解決策

**入力仕様を「ひらがな + アクセント記号 + 無声化マーク」に変更する。**

漢字を扱わないので形態素解析が不要になり、辞書が **877 B の mora テーブル**に置き換わる。
アクセントと無声化は入力が持つので、端末側で推定しない。

```
漢字かな交じり文  ──[ホスト側・オフライン]──▶  中間表現  ──[端末側・877 B]──▶  音素ID列 ──▶ 音声
今日は良い天気ですね。                    きょ][おわよ][いて][んきです°ね
```

## 3. システム構成と境界

```
┌─ ホスト側（PC / ビルド時・オフライン）──────────────────────┐
│  漢字かな交じり文                                            │
│      ↓  OpenJTalk + NAIST-JDIC (102 MB)                     │
│  音素列 + アクセント                                          │
│      ↓  phonemes_to_intermediate()                          │
│  中間表現「きょ][おわよ][いて][んきです°ね」  ← これを端末へ渡す        │
└──────────────────────────────────────────────────────────┘
                              │ 平均 108 B/文
┌─ 端末側（ESP32-S3・実行時）───────────────────────────────┐
│  中間表現                                                    │
│      ↓  テーブル 877 B（mora 195 + 記号 10 + ん 異音 21）            │
│  音素ID列                                                    │
│      ↓  Duration Dα (32,964) → Acoustic Aβ (194,736)        │
│         → iSTFT Decoder Gγ (331,308)   計 559,008 params    │
│  22.05 kHz PCM                                              │
└──────────────────────────────────────────────────────────┘
```

⚠️ **論文（英語・語彙 157）は 567,008 params。日本語は語彙 57 なので 559,008**（D-016）。
埋め込みが 100 語彙 ×（Dα 32 + Aβ 48）= 8,000 減る。⚠️ **MMAC は 1 も減らない**（表引き）。

**境界の定義**: 論文と同じく「外部 G2P はシステム外」とするが、
本プロジェクトは**端末内に 877 B のテーブルだけで G2P を持つ**点で論文より広い境界を主張できる。

## 4. 入力仕様

### 4.1 中間表現の文法

```
中間表現 ::= ( モーラ | アクセント記号 | 境界記号 )*
モーラ   ::= ひらがな1〜2文字 [ "°" ]
```

| 記号 | 意味 | 音素ID |
|---|---|---:|
| `[` | アクセント上昇 | 8 |
| `]` | アクセント下降核 | 9 |
| `#` | アクセント句境界 | 7 |
| `°` | 直前モーラの母音を無声化 | （`i`→`I` 等） |
| `_` | ポーズ | 0 |
| `^` `$` | BOS / EOS | 1 / 2 |
| `?` `?!` `?.` `?~` | 疑問 EOS 4 種 | 3 ほか |

### 4.2 モーラ表

**116 エントリ / 877 B。** 清音・濁音・半濁音・拗音・外来語音（`ふぁ` `てぃ` 等）・
`っ`（促音）・`ん`（撥音）・`ー`（長音）を含む。

`ん` の異音は**後続子音から規則で決まる**（18 規則）:

| 後続 | 異音 |
|---|---|
| `m` `b` `p` `my` `by` `py` | `N_m` |
| `n` `t` `d` `ts` `ch` `ny` `ty` `dy` | `N_n` |
| `k` `g` `ky` `gy` | `N_ng` |
| その他・語末 | `N_uvular` |

`ー` は直前の母音を繰り返す。

### 4.3 なぜアクセントと無声化を入力に持たせるのか

**どちらも規則では決まらないことを実測で確認した。**

| 方式 | 往復一致率 |
|---|---:|
| ひらがなのみ（フル 103 MB 辞書でアクセント推定） | **15.0%** |
| ひらがな + アクセント記号（無声化は規則で推定） | 59.6% |
| **ひらがな + アクセント記号 + 無声化マーク** | **100%** |

無声化を「無声子音に挟まれた i/u」という規則で推定すると、実測で **170 箇所を過剰無声化**した。
無声化は品詞とアクセント型に依存するため規則化できない。

**アクセント記号は音素IDそのもの**であり、位置を1つ変えると F0 が **42.8 Hz** 変わる。
VITS はピッチを潜在 z に持ち、z は音素IDから決まるので、
**記号が入力にあれば生徒は正しいピッチを学習する。アーキテクチャの変更は不要。**

### 4.4 実測されたカバー率

| 評価セット | 中間表現で表現可能 | 往復の完全一致 | サイズ |
|---|---:|---:|---:|
| held-out 1,500 文 | **96.40%** | **100.00%** | 平均 108 B/文 |
| embedded 184 文（ESP32 実運用想定） | **98.91%** | **100.00%** | 平均 65 B/文 |

再現: `scripts/kana_g2p.py`

**表現できない 3.6%** は、アクセント句境界 `#` がモーラ内部（子音と母音の間）に
現れるケースが主。中間表現がモーラ単位のため表現できない。要調査（§9）。

## 5. 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| F-1 | 中間表現を受け取り 22,050 Hz PCM を出力する | 必須 |
| F-2 | 端末側 G2P は mora テーブルと `ん` 異音規則のみで動作する（辞書・形態素解析を使わない） | 必須 |
| F-3 | アクセント記号 `[` `]` `#` を音素IDに透過的に渡す | 必須 |
| F-4 | 無声化マーク `°` を対応する無声化母音の音素IDに変換する | 必須 |
| F-5 | ホスト側変換器が漢字かな交じり文から中間表現を生成する | 必須 |
| F-6 | 未知文字を検出し、無音で脱落させずエラーとして扱う | 必須（§8.5） |
| F-7 | 疑問文 EOS 4 種を区別する | 推奨 |
| F-8 | ポーズ `_` による間の制御 | 推奨 |
| F-9 | **端末がシリアルから中間表現を 1 行受け取って合成する**（実装済み。M-63 / D-040） | 推奨 |
| F-10 | **端末側で受け付けない文字は、位置と文字を示して拒否する**（黙って無音にしない） | 必須（F-6 の端末側） |

⚠️ **F-9 / F-10 は後から足した**（2026-08-30）。当初はビルド時に焼き込んだ 1 文しか
喋れなかった。⚠️ **実機の UART では未検証**。

## 6. 非機能要件

### 6.1 フットプリント

| 項目 | 目標 | 根拠 |
|---|---:|---|
| モデル (int8 blob 2 個) | **679,832 B** | 論文の実績値 |
| 端末側 G2P データ | **877 B** | 実測 |
| 合計（フラッシュ） | **< 1 MB** | 上記の和 |
| RAM ピーク | **< 512 KB** | I2S 逐次出力なら約 **96 KB**（論文の作業領域 93.5 KB + 本プロジェクトの G2P 2.5 KB）。PCM を全保持すると発話長に比例し 8 秒で 440 KB。**実機未測定**（M-16） |

**8 MB フラッシュのボードでも大きな余裕がある。** 辞書路線で必要だった 11.57 MB が不要になった。

### 6.2 速度

| 項目 | 目標 | 根拠 |
|---|---:|---|
| ESP32-S3 の RTF | **≤ 0.5**（論文は 0.22） | 45 MMAC/s は言語非依存なので日本語でも同等のはず。**未測定** |
| 端末側 G2P の処理時間 | 合成時間の 1% 未満 | 877 B のテーブル引きのみ。**未測定** |

### 6.3 品質

**評価は「教師比」で報告する。** 論文が多言語について
"absolute SCOREQ values are not calibrated for comparisons across languages" と
明言しているため。UTMOS も日本語では較正されていない。

**さらに「人間音声比」も併記する**（D-013）。UTMOS は日本語でスケールが圧縮されており、
**実人間の日本語音声ですら 2.305 しか出ない**（M-10）。天井を測らないと比が読めない。

```
教師 / 実人間 = 1.748 / 2.305 = 0.758   ← 現在地
```

| 指標 | 目標 | 備考 |
|---|---|---|
| UTMOS（教師比） | **≥ 0.63** | 論文の英語 embedded は 2.80/4.42 = 0.63。絶対値なら UTMOS 1.10 前後 |
| UTMOS（人間比） | 参考値として併記 | 目標 0.63×teacher なら人間比 0.48× |
| SCOREQ（教師比） | **≥ 0.55** | 論文の英語 embedded は 2.54/4.68 = 0.5427。**導入済み**（教師 2.0488 / 実人間 2.4983 → 目標の絶対値は 1.112）。⚠️ `data_domain="natural"` は使わない（D-020） |
| CER | 教師との差 ≤ 10 pt | 日本語は分かち書きが問題になるので WER ではなく CER |
| 音素クラス別スペクトル平坦度（2–8 kHz） | 摩擦音で教師比 ≥ 0.85 | 論文は 0.689 → 0.590 の劣化を集約スコアで見逃した |
| アクセント型ミニマルペア | 聴取で弁別可能 | 橋/箸/端、雨/飴 |

## 7. 品質の測定方法

### 7.1 必ず守ること

**集約スコアだけで判断しない。** 論文は SCOREQ 4.09 / UTMOS 3.98 の裏で
sibilant が whistly になる欠陥を見逃した。音素クラス別プローブで初めて検出された。

**評価セットにテンプレート文を使わない。** 論文は narrow test set で SCOREQ を
**1.35 過大評価**した（3.07 → 実際は 1.72）。

### 7.2 評価セット

| セット | 用途 | 状態 |
|---|---|---|
| `data/splits/corpus_heldout.tsv`（2,325 文） | 汎化性能 | 構築済み |
| `data/splits/corpus_embedded.tsv`（183 文） | ESP32 実運用想定（時刻・金額・通知文・助数詞） | 構築済み・**ネイティブレビュー未了** |
| アクセント型ミニマルペア | ピッチアクセントの弁別 | **未構築** |

### 7.3 摩擦音のノイズ注入（論文 式7）

```
S_ja = {s, sh, ts, ch, z, j, h, hy, f, I, U}
```

無声化母音 `A` `E` `O` はコーパス 23,271 行で**1 度も出現しない**ため除外した。
`β` は聴取で決める（論文も同様）。

## 8. 制約と前提

### 8.1 教師モデル

| 項目 | 値 |
|---|---|
| ckpt | `ayousanz/piper-plus-zero-shot-tsukuyomi` の `epoch=499-step=22000.ckpt` |
| ロード先 | piper-plus v2.0 HEAD（`v1.13.0` への checkout は**不要**） |
| 呼び出し | `noise_scale=0` / `noise_scale_w=0` / `length_scale=1` / `lid=0` / `speaker_embeddings=None` |
| EMA | `apply_ema_shadow_params()` を `remove_weight_norm()` の**前に**明示的に適用 |

### 8.2 蒸留データ

**音声データは不要。テキストのみ。** ラベルは教師の決定的推論から生成する。

| 項目 | 値 |
|---|---:|
| 調達済み | 23,271 行（JSUT + ROHAN4600 + ITA + Common Voice ja） |
| 学習用 | 20,946 行（論文の 14,343 行を上回る） |
| 目標 | **1 万行以上**（論文は 512 行で汎化に失敗） |

### 8.3 開発・実行環境（プロジェクト制約）

#### Python は `uv` で管理する

```bash
uv sync ; uv run python scripts/xxx.py ; uv add <pkg>
```

`pip install` を直接使わない。依存は `pyproject.toml` / `uv.lock` に記録する。
piper-plus は `[tool.uv.sources]` の path 依存 (editable) で参照し、**リポジトリは変更しない**。

| 環境 | Python | torch | 教師ラベル |
|---|---|---|---|
| piper-plus `.venv` | 3.13.9 | 2.11.0 | 基準 |
| 本プロジェクト `uv` | 3.14.0 | 2.13.0 | **bit 完全一致**（実測） |

#### 学習とラベル生成は手元の M4 Max で行う（D-027）

実測すると手元で完結する。**vast.ai は不要だった。**

| 工程 | device | 実測 |
|---|---|---|
| ラベル生成 train 20,894 文 | **CPU** | 116 ms/文 → 約 40 分 / 4.5 GB |
| 学習 4 段（各 20k step） | **MPS** | 58 / 81 / 58 / 39 ms/step → 約 1.3 時間 |

マシン: Apple M4 Max / 16 core / 64 GB / 空き 222 GB。

⚠️ **ラベル生成は CPU。MPS は使わない。** CPU と MPS は bit 一致しない
（M-21、SNR 97〜106 dB）。CPU 生成は M-15 で piper-plus venv と bit 完全一致が
確認済みで、**未検証の CUDA parity ゲートも回避できる**。

### 8.4 vast.ai インスタンスの要件（現在は使っていない）

λ の並列探索や長時間学習で使う場合の要件。手順は
[`vastai-runbook.md`](vastai-runbook.md)。⚠️ **CUDA parity ゲートは未通過。**

| 項目 | 要求 | 根拠 |
|---|---|---|
| ディスク | **≥ 40 GB** | ラベル fp16+int16 4.5 GB + ckpt 0.93 GB + 環境 + 中間生成物 |
| GPU VRAM | **≥ 16 GB** | 生徒は 559 K と小さいが、decoder 学習が multi-resolution STFT (FFT 512/1024/2048) + 判別器を持つ。**未実測** |
| GPU | CUDA 対応（世代不問） | 生徒が小さいので最新世代は不要 |
| Python | 3.11 以上 | `pyproject.toml` の `requires-python` |
| 事前準備 | HF トークン（教師 ckpt は private repo） | |

転送するもの: 学習テキスト **1.2 MB** のみ（ckpt 927 MB は HF から直接、
ラベルパック 4.5 GB はインスタンス内で生成）。持ち帰るのは生徒の重み数 MB。

**再現性の要件**（実行場所によらず守る）:
1. ラベル生成は**一度だけ**実行し、パックに SHA-256 を付けて固定する（D-015）
2. 生成環境（Python / torch / device）を manifest に記録する
3. 乱数シードとフラグを run レポートに残す（論文の "audited" 方針を踏襲）
4. piper-plus のコミットを `src/saanotts_jp/teacher_identity.py` で照合する

### 8.5 未知語は「無音で消える」

`unk.dic` の 40 エントリは読み・アクセントを持たないため、未知語は読点に置換され
**例外も警告も出さずに音声から消える**。ホスト側 G2P でも外字・幽霊漢字で起きる。

→ **F-6**: ホスト側変換器は未知文字を検出して**エラーにする**。黙って落とさない。

### 8.6 教師コーパスのライセンス

検証 (PoC) で配布しないため着手のブロッカーにしない。**公開時は再確認が必要** —
つくよみちゃんコーパス `CC-BY-4.0 / verified: false`、
MOE-Speech `CC-BY-SA-4.0 / verified: false`（CC-BY-SA は蒸留物への継承の議論がある）。

## 10. 受け入れ条件

本プロジェクトが「成功した」と言える条件:

1. **ESP32-S3 実機**で中間表現から 22.05 kHz PCM が出る
2. RTF ≤ 0.5、RAM ピーク < 512 KB、フラッシュ < 1 MB
3. 浮動小数点参照との Pearson 相関 ≥ 0.98（論文と同じゴールデンテスト）
4. held-out セットで SCOREQ が**教師比 0.55 以上**
5. 音素クラス別スペクトル平坦度で、摩擦音が教師比 0.85 以上
6. アクセント型ミニマルペアが聴取で弁別できる

**1 と 2 が満たせなければ、他がどれだけ良くてもプロジェクトの目的を達成していない。**
