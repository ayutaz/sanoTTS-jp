# v1.0.0 — 商用利用の条件を確定させ、継承リスクを外した

2026-09-11。**最初の 1.0 です。**

⚠️ **1.0 は「もう変わらない」という意味ではありません。** ここで確定したのは
**配布の条件**（誰がどう使えるか）と**成果物の形**（28 本の資産）であって、
**下の「⚠️ 1.0 でも未決のもの」は 4 件残っています**（⚠️ **音を聴いていないことが最大のもの**です）。

## なぜ 1.0.0 にしたか

| | |
|---|---|
| **配布の条件が確定した** | 声を替えないと決め（`docs/decisions.md` D-058）、**義務の一覧が動かなくなった**。それまでは「声を差し替えれば出力制限が消えるかもしれない」という未確定を抱えていた |
| **継承（share-alike）リスクが消えた** | 蒸留テキストから JSUT を外した重み **v4**（D-057） |
| **帰属義務を満たした** | 欠けていた 3 素材と Apache-2.0 全文を入れた（C-080 / C-081） |
| **実機で動いた** | M5Stack CoreS3 で漢字を喋り、**xRT 0.448** で実時間の要件を満たした（M-124） |
| **出荷物がそろった** | firmware 10 本 / 辞書 5 本 / 重み・音声 6 本 / ライセンスと NOTICE 6 本 + `SHA256SUMS.txt` = **28 本** |

## ⚠️ 1.0 でも未決のもの

- ⚠️ **音を誰も聴いていません。** v4 の合成音は 1 秒も聴取していません（G32）
- ⚠️ **焼いて確かめたのは 10 本中 1 本**（M5 CoreS3 の 16 MB 版）だけです。
  残り 9 本は**中身を抽出して照合しただけ**で、焼いても QEMU にも入れていません
  （[M-126](../measurements.md#m-126) / [M-128](../measurements.md#m-128)）
- ⚠️ **アクセントが v3 より落ちています**（37/37 → 31/37。下記 3）
- ⚠️ **辞書の完全性を端末が検査しません。** 壊れた辞書や**容量違いの辞書**を焼くと、
  止まらずに起動して**読みが悪くなるだけ**です（v0.3.1 から辞書単体を 5 本配っているので
  取り違えが起こりえます）。⚠️ **入れ方は決めてあります**が、**実装はこの版の後**です
  （[D-063](../decisions.md#d-063)。firmware に焼いた SHA-256 で検査し、
  不一致なら**かな専用**で続く。コストは実測 471 ms = [M-131](../measurements.md#m-131)）

**この 4 つが解けていないまま 1.0 と名乗ることは、意図した判断です** —
1.0 が主張するのは**条件の確定**であって、品質の完成ではありません。

✅ **速度の要件は満たしています。** かつてここに「RTF の分母が未決」と書いていましたが、
**2026-09-11 に決めました**（[D-049](../decisions.md#d-049)）— **定常の分母で ≤ 0.5**
（実測 **0.448**）/ **アンダーラン 0** / **鳴らし始めまで ≤ 0.8 s**（実測 約 479 ms）。
⚠️ **発話全体の 0.54〜0.71 は参考値**です（≤ 0.5 に必要な音声長が 3.43〜4.40 秒 =
**合否が文の長さだけで決まる**ため、要件の分母には使えません）。

---

⚠️ **タグの `v1.0.0` と、資産名の `v4` は別の軸です。**
`v4` は**モデルの版**（v3 = JSUT 込み / **v4 = CC0 / PD のみ**）で、
v0.3.x が `saanotts-jp-v3-*` を配っていたのと同じ関係です。
**v1.0.0 が配るのは v4 の重み**です。

---

**この版の中身の理由はライセンスであって、品質ではありません。**

蒸留に使うテキストから **JSUT ver1.1（CC-BY-SA-4.0 = 唯一の継承付き素材）6,380 行を外し**、
**CC0 / パブリックドメインのみの 14,513 行**で学習し直した重み **v4** を配ります。
これで**蒸留テキスト由来の継承（share-alike）リスクが消えます**。

⚠️ **出力の用途制限とコピーレフトは 1 つも減りません。** それは教師の fine-tune に
使った**つくよみちゃんコーパス 100 発話**から来ており、2026-09-10 に
**声はつくよみちゃんのままにすると決めました**（`docs/decisions.md` D-058）。
**したがってこの 2 つは今後の版でも残ります** — 「将来の版で消える」ものとして扱わないでください。

✅ **実機（M5Stack CoreS3）で漢字を喋りました**（`docs/measurements.md` M-124）。
満チャンク 1 pull の **xRT 0.448** / アンダーラン **0** / **漢字で書いてもかなで書いても
PCM が bit 一致**。⚠️ **ただし音は誰も 1 秒も聴いていません。**

## 何が変わったか

### 1. 蒸留テキストが CC0 / PD のみになりました

| | v3 | **v4** |
|---|---:|---:|
| 蒸留に使った行数 | 20,893 | **14,513** |
| うち JSUT ver1.1（CC-BY-SA-4.0） | 6,380 | **0** |
| 学習に入った発話 | 20,792 | **14,426** |

論文の 14,343 行を上回る行数を保てました。**音素カバレッジに穴は空いていません** —
出現する音素は **54 種で v3 と同一**、最も稀な 3 音素も同じでした（`docs/measurements.md` M-115）。

判定は 1 か所（`src/saanotts_jp/corpus_license.py`）の allowlist で行い、
**ラベルパックそのものを検査できます**（`scripts/check_corpus_license.py --pack`）。
⚠️ **前方一致ではなく完全一致**で判定します（`cv/europarl-v7-ja` のような
「CC0 のコーパスに見えるが違う」ものを取り込まないため）。

### 2. 品質は SCOREQ も CER も差を検出できませんでした

| 指標 | v3 | **v4** | 判定 |
|---|---:|---:|---|
| SCOREQ synthetic/nr（生徒） | 1.2716 | **1.2552** | |
| SCOREQ 教師比 | 0.6444 [0.6044, 0.6843] | **0.6361** [0.5902, 0.6853] | |
| **SCOREQ v4 − v3（対応あり）** | — | **−0.0164** [−0.0671, +0.0361] | ⚠️ **CI が 0 を跨ぐ = 検出できず** |
| かな CER（生徒） | 0.1671 | **0.1670** | 実質同一 |
| int8 blob 合計 | 624,692 B | **624,692 B** | 完全一致 |

⚠️ **n=24。** 絶対値は日本語で較正されていないので、論文の英語モデルと比べないでください。

### 3. ⚠️ アクセントは落ちました（37/37 → 31/37）

**検出できた差はここだけです。**

| run | 変えたもの | アクセント符号一致 |
|---|---|---:|
| v3 | — | **37/37 = 1.000** |
| **v3_seed2** | **seed だけ**（パックは v3 のまま） | **34/37 = 0.919** |
| **v4** | テキスト（CC0/PD のみ） | **31/37 = 0.838** |

**同一パックで seed だけ変えると 34/37 まで落ちました** = 劣化の**大部分は run 間の
ばらつき**です（`docs/measurements.md` M-117）。v4 が失った 3 ペアは v3_seed2 が
失った 3 ペアを含みます。

⚠️ **テキストの影響を否定はできません。** seed 対照は n=1 run で、
「JSUT を外したこと自体の寄与」は分離できていません。

⚠️ **教師の差が大きいペアでは落ちていません**: `|Δ_T| ≥ 3.5 st` で **17/17 = 1.000**。
落ちたのは教師自身の差が小さいペア（`1型 vs 2型` の cos 平均 0.3824）です。

⚠️ **`magnitude_ratio` は 1.193 → 1.283** に増えました（生徒の起伏が教師より 28% 大きい）。
**過剰強調かどうかは聴かないと分かりません。**

### 4. アクセント指標の欠陥を直しました（測り方の訂正）

**教師ゲートが生徒に依存していました**（`docs/decisions.md` C-076）。
「教師の差が十分大きいペアだけ数える」というゲートが、**生徒の F0 が取れたモーラだけ**の
マスクで計算されていたため、**生徒が悪いとゲートも動いて分母が変わる**状態でした。

直した結果、**3 run すべてで分母が 37/38 にそろいました**（v4 は 36 → 37）。
上の表の数字は**すべて修正後**です。⚠️ **陽性対照つき**で、旧実装だと 5.196 st → 0.000 st と
判定が反転することを CI で毎回確認しています（`scripts/test_accent_gate.py`）。

| | v3 実機（M-90） | **v4 実機** |
|---|---:|---:|
| 満チャンク 1 pull の xRT | 0.446 | **0.448** ✅ 要件 RTF ≤ 0.5 |
| アンダーラン | 0 | **0 / 14 チャンク** |

### 6. ✅ `？〜` で終わる文が疑問になるようになりました

⚠️ **v0.3.x までは平叙で読んでいました。**

| | `まじで？〜` を打つと |
|---|---|
| `v0.3.x` まで | ❌ **平叙**（`$` で終わる）。疑問の抑揚が付かない |
| **`v1.0.0`** | ✅ **疑問**（`?~`） |

原因は **`〜` の符号位置**でした。ホスト側は `U+301C`（WAVE DASH）を
`U+FF5E`（FULLWIDTH TILDE）に寄せてから解析しますが、**端末が寄せていませんでした**。
⚠️ **日本語で普通に使われるのは `U+301C` の方**です
（このモデルの学習データでも `?~` の行 10 本は**全部 U+301C 綴り**でした）。

**n=1,495 の照合で 1,494 → 1,495**（ホストと完全一致）。
✅ **波形は 1 bit も変わりません** — `？〜` を含まない入力には触れないためです
（[`docs/decisions.md`](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/decisions.md#d-062) D-062 /
[M-127](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/measurements.md#m-127)）。

⚠️ **ホスト側の他の正規化（`U+2212` / `U+00A0`）は端末に入れていません。**
`U+2212` の寄せ先 `U+FF0D` が**端末の辞書に無い**ため、寄せると今より悪くなりえます。

### 焼き方

```bash
# ⚠️ 先に元のファームを退避してください
esptool.py --chip esp32s3 -p /dev/cu.usbmodemXXXX read_flash 0 0x1000000 backup.bin

esptool.py --chip esp32s3 -p /dev/cu.usbmodemXXXX write_flash 0x0 m5-cores3-firmware-kanji-16mb.bin
```

⚠️ **`--flash_mode qio` を渡さないでください。** ヘッダが QIO になって ROM ローダが
読めず、ブートループします（`docs/measurements.md` M-86）。**上のコマンドのまま**使ってください。

⚠️ **M5 版は起動すると自分から 1 度喋ります**（スタックチャン用の既定）。
DevKit 版は喋らず `かな> ` のプロンプトを出します。

⚠️ **この 3 イメージは QEMU で動かせません**（**QIO** で焼くため。QEMU の flash モデルは
QIO を受け付けません）。QEMU で通したのは**同じソース・同じ blob の DIO ビルド**で、
違いは**フラッシュモードと起動時発話の 2 点だけ**です
（`docs/measurements.md` M-120 / M-121 / M-122）。**実機で確かめたわけではありません。**
