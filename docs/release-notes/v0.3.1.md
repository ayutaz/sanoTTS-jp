# v0.3.1 — 小さい flash（8 / 4 / 2 MB）を正式に配る

**2026-09-10。** [v0.3.1-rc1-smallflash](https://github.com/ayutaz/sanoTTS-jp/releases/tag/v0.3.1-rc1-smallflash)
（検証用 prerelease）を**正式リリースに上げた**もの。

⚠️ **モデルの重みは v0.1.0 以降 1 bit も変わっていない**（再学習していない）。
このリリースで増えたのは**小さい flash 向けのイメージと辞書**だけである。

## 何が増えたか

| ファイル | 板 | entries | **音素の誤り** |
|---|---|---:|---:|
| `esp32s3-firmware-kanji-8mb.bin` | 8 MB **DevKit**（app 1.02 MB 前提） | 228,000 | 1.01% |
| `m5-cores3-firmware-kanji-8mb.bin` | 8 MB **M5Stack 系**（app 1.44 MB 前提） | 213,000 | 1.09% |
| `esp32s3-firmware-kanji-4mb.bin` | **4 MB** | 135,000 | 1.94% |
| `esp32s3-firmware-kanji-2mb-budget.bin` | **2 MB の枠**（⚠️ 4 MB のイメージとして焼く） | 44,000 | 3.86% |

辞書単体も 4 本（`k1-dict-228000-8mb.bin` / `-213000-8mb-m5` / `-135000-4mb` / `-44000-2mb`）。

**出荷の基準は今も 16 MB**（438,750 entries / 音素の誤り **0.63%**。[D-044](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/decisions.md#d-044)）。
小さい flash は**読みの精度を捨てて容量に収める**もので、上の表がその代償である。
⚠️ **「音素の誤り」は n=1,495 の値**（[C-059](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/decisions.md#c-059) / [M-106](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/measurements.md#m-106) §14）。
n=298 で測ると 2 倍楽観的に出る。

## ⚠️ どこまで確かめたか

✅ **第三者の実機で鳴った**（[M-109](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/measurements.md#m-109)）:

| 板 | チップ | PSRAM | Flash | 4M | 2M |
|---|---|---|---|---|---|
| CoreS3 | S3 | 8MB Quad | 16MB | ✅ 起動・音 | ✅ 起動・音 |
| **ATOMS3 + Voice Base** | S3 | **無し** | 8MB | ✅ 起動・音 | ✅ 起動・音 |

**PSRAM の無い板で動いたのが大きい**（内部 DRAM の余裕が薄いことを [M-98](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/measurements.md#m-98) で
測っていた。[D-052](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/decisions.md#d-052) の `SAAN_KANJI_MAX_INPUT_TOK = 44` が効いている）。

⚠️⚠️ **次の 4 つは今も分かっていない。正式リリースにしても変わらない**:

1. **PCM の checksum**（16 MB の基準と一致するか）
2. **定常 xRT**（16 MB の実機は 0.446。⚠️ QEMU の値は使えない）
3. **アンダーラン**（0 が期待値）
4. **どのくらいの長さの文を打ったか**（PSRAM 無しの余裕は入力長で決まる）

⚠️ **報告は 1 名・対照なし・盲検なし**で、**私自身は 4 MB / 2 MB を 1 度も再現していない**。
⚠️ **8 MB は実機で測ってある**が、**16 MB の板に 8 MB の表を焼いたもの**で、
8 MB flash のチップそのものでは測っていない（[M-105](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/measurements.md#m-105)）。

⚠️ **ESP32-S3 に 2 MB flash の品番は無い**（WROOM-1 は N4 / N8 / N16）。
`2mb-budget` は「**その枠に収まる**」ことしか言っていない。

## ⚠️ 辞書単体を焼くときの注意

**表（パーティション）と辞書は必ずセットにすること。** DevKit 用の辞書を M5 版に焼くと
241,808 B 入らない。そして**端末は blob の身元を見ていない**ので、
**取り違えても止まらず、読みだけが静かに落ちる**（[M-100](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/measurements.md#m-100) §8 の 1・2）。
迷ったら**辞書入りの flash イメージ 1 本**を使うこと（オフセット 0 に焼くだけ）。

## v0.3.0 から持ってきたもの

**[D-045](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/decisions.md#d-045) の 1「リリースは単独で完結させる」に従い、v0.3.0 の 18 資産を
そのまま置き直した**（重み・16 MB ファーム・golden・辞書 13.7 MB・ライセンス・NOTICE）。
GitHub の `releases/latest` は最新タグを指すので、**置き直さないと README の案内が全部 404 相当になる**
（v0.2.0 で実際に壊した = [C-052](https://github.com/ayutaz/sanoTTS-jp/blob/main/docs/decisions.md#c-052)）。

**同一性は SHA-256 で示した**（D-045 の 2）。落とす → v0.3.0 / rc の `SHA256SUMS.txt` と照合
（**26/26 OK**）→ 統合して置き直す → 落とし直して再照合。
`SHA256SUMS.txt` は**作り直してあり、自分自身の行は入っていない**（D-045 の 3）。
