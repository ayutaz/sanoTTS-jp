## 全体の目的

記事が示した 2 種類の穴を、**`v1.2.0` の保証を壊さずに**塞ぐ。

| 種類 | 記事・改造版で見えたこと | こちらの今 |
|---|---|---|
| 使い勝手 | 改造版は長文を `。` で区切って全部喋る / ユーザー辞書を持つ | 形態素 44 個 or 350 ids を超えると**喋らない**。誤読（上毛 → ジョー + 毛）は辞書を作り直さないと直らない |
| 音質の疑い | 「sanoTTS-jp をそのまま使うと声が少し遅れて重なって聞こえる『二重感』」 | **こちらの声で起きているかは不明。** DNSMOS は位相破壊にほぼ反応しない（M-50）ので、今の指標では見つけられない可能性が高い |
| 速度 | 改造版は一部の重みを PSRAM に写している | 残タスク #21（253 ids で定常 xRT の中央値 0.522） |

## 縛り（全ブランチ共通）

- **上限内の入力は PCM が `v1.2.0` と bit 一致する**（W8A8+PIE の錨 `0x390bf4b2aef8f2ec` / 27,136 sample ほか）
- **コア（`csrc/saanotts*.c`・`fft.c`）は 1 バイトも変えない**
- 定常 xRT・アンダーラン 0・静的 DIRAM 211,535 B が悪くならない
- **速度の判断は実機の数字だけ**（C-055）。QEMU のサイクルや命令数で語らない
- **学習はしない**（重みは `v4` のまま）。学習が要る倍音励起は本設計の外（下の「やらないこと」）
- 新しいゲートは**陽性対照を実行して落ちるのを見てから**書く（`.claude/skills/writing-gates/SKILL.md`）
- 記録は今の決まりどおり **D-070〜 / M-151〜** に書く。⚠️ **ブランチは並行して走るので、番号は先にブランチごとに予約する**（C-078 で番号が衝突した）:

### `feat/userdict` の計画を今書かない理由

インターフェースが**置き場所の決定**で変わるため。案は 2 つで、2 週目の頭に人が選ぶ:

- **(a) パーティションを足す** — 16 MB 構成の `dict`（0xD30000 = 13,828,096 B）には辞書 13,702,320 B に対し
  125,776 B の余りがあり、64 KB 縮めれば `userdict` が入る（`dict` の開始位置は変わらない）。
  ⚠️ パーティション表が変わるので、利用者は全部焼き直す
- **(b) NVS に置く** — 表は変わらないが、NVS（24 KB）が小さく mmap できない

どちらにするかで C リーダ（mmap か読み込みか）と Viterbi への差し込み方が変わる。
決めてから同じ形式の計画を書く。

## やらないこと（と理由）

| 改造版の変更 | やらない理由 |
|---|---|
| **倍音励起**（F0 ヘッド + 倍音源を複素スペクトルに掛ける。`SAAN_G_EXCITE`） | **`eval/doubling-check` で問題が出たときだけ**別の設計で扱う。v5 として Stage 3 / 4 の再学習（M4 Max で約 1.8 時間）が要る。平均 xRT が既に 0.499 なので D-049 を破り、要件の見直しとセットになる。⚠️ 設計の出所を確認できていないので、**コードは写さず説明から書き直す** |
| decoder 出口 48 → 512 幅 | 速度・メモリの予算が無い（改造版のモデルは 1,476,992 B） |
| 音素段の膨張畳み込み（GD、±31 音素） | こちらのアクセントは向きが 37/37 で一致。課題は逆（起伏が 19% 大きい = `magnitude_ratio` 1.193） |
| SBV2 の句規則 / 文末ポーズ | 改造版の教師（Style-Bert-VITS2）の入力に合わせた規則 |
| Web デモの長文分割 | `web/saan_web.c` は発話全体の PCM を固定配列に貯めるので別の作業になる。`feat/long-text-split` の後に必要なら別計画 |
| クラウド GPU での学習 | 上の倍音励起に進んだ場合でも、**CUDA の bit 一致ゲート（`scripts/b4_device_parity.py --device cuda`）を一度も通していない**。手元の M4 Max で足りる（D-027） |
