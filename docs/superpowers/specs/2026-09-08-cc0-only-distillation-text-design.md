# 設計: 蒸留テキストを CC0 / PD のみにする（JSUT を外す）

- 作成日: 2026-09-08
- 状態: **設計（承認済み）**。実装は未着手
- ブランチ: `feat/commercial-use-model`
- 上位の決定: [D-054](../../decisions.md#d-054)（ゴール = 帰属表示のみ・出力制限なし・継承なし）
- 調査: [L-1](../../research/l1-commercial-use-licensing.md)

---

## 1. 目的

**モデルの重みに継承（copyleft）が及ぶ経路を、蒸留テキストから消す。**

[D-054](../../decisions.md#d-054) が定めたゴールのうち、**声と独立に達成できる半分**がこれである。
JSUT ver1.1 のテキストは CC-BY-SA-4.0 で、本プロジェクトが使う素材の中で**唯一の継承付き**。
「学習済みモデルは学習テキストの二次的著作物である」という立場を取られた場合、
重みに share-alike が及ぶ（[D-035](../../decisions.md#d-035) の「残るリスク」）。

⚠️ **これだけではゴールに届かない。** 出力の用途制限は教師の fine-tune
（つくよみちゃんコーパス 100 発話）から来ており、そちらは声の差し替えを待つ。

## 3. スコープ

### 含む

- `source` 列にもとづく allowlist の実装と、ラベル生成への適用
- 受け入れゲート 3 本（すべて陽性対照つき）
- **統計の比較**（音素 / 文字種 / 長さ / 多様性軸のカバレッジを v3 と差分で）
- ⚠️ **判断点**: ここでラベル再生成と学習に進むか、声の確定を待つかを決める
- 判断点の後に進む場合: ラベル再生成 → 学習 4 段 → 品質ゲート → golden / blob / firmware の再凍結

### 含まない

- **教師の声の差し替え**（つくよみちゃん → 別の声）。声の調達は未確定
- **教師の再学習**。piper-plus 側の作業で、本リポジトリの範囲外
- [C-071](../../decisions.md#c-071) の `LICENSE-MODEL.md` / `NOTICE.md` 訂正。**独立に進める**
- `data/splits/corpus_*.tsv` の再生成。split 生成スクリプトはリポジトリに無い（§4.2）

## 4. アーキテクチャ

### 4.1 方式: `source` 列の allowlist

`scripts/gen_teacher_labels.py` は**既に `source` を読み、パックの `index.jsonl` に書いている**（実測）:

```
{"seq": 0, "uid": "sentence_collector_08727", "source": "cv/sentence_collector", ...}
```

したがって判定を `source` に置くと、**出荷したパックそのものを検査できる**。

- 判定表は 1 か所（`src/saanotts_jp/` の定数）に置き、ラベル生成・統計・ゲートが同じ表を読む
- allowlist（許可する接頭辞）方式にする。**新しい出所が黙って混ざらない**
  — 未知の `source` は拒否側に落ちる

**却下した代替案:**

| 案 | 却下の理由 |
|---|---|
| uid の除外リスト（`exclusions_teacher_ft.txt` の形） | 6,472 行の uid が並ぶだけで**理由がファイルから読めない**。CV に行が増えても追随しない。**リストが正しいことを別途信じる必要がある**（allowlist ならパックを直接検査できる） |
| `corpus_train_cc0.tsv` を書き出す | **split 生成スクリプトがリポジトリに無い**。近傍重複の除外と分割比を再現するところから作ることになり、v3 の再現性が別ファイルに分岐する |

### 4.2 既存の除外機構との関係

`gen_teacher_labels.py` の `load_exclusions()` は `data/splits/exclusions_teacher_ft.txt` を
**uid 単位**で読む（B-10。教師の FT テキストとの重複を外す = 丸暗記を測らないため）。

**両者は併存させる。役割が違う。**

| 機構 | 単位 | 目的 |
|---|---|---|
| `exclusions_teacher_ft.txt`（既存） | uid | 教師の丸暗記を測らない |
| **allowlist（新規）** | `source` | **ライセンス** |

⚠️ `data/splits/exclusions_near_dup.txt` は**誰も読んでいない**
（`scripts/b10_write_exclusions.py` が書くだけ。実測）。**この設計では触らない。**

### 4.3 held-out は据え置く

**評価にしか使わない行は重みに入らない**ので、ライセンスの論点（モデルが学習テキストの
二次的著作物か）は発生しない。外すと held-out が 2,333 → 1,616 行になり、
**v3 との品質比較ができなくなる**。

⚠️ これは「JSUT テキストを再配布する」ことではない。
[`../../../NOTICE.md`](../../../NOTICE.md) の通り**コーパス本文はリポジトリに入っていない**。

### 4.4 成果物の名前

- ラベルパック: **`data/pack_cc0`**
  ⚠️ `data/pack` は hook が破棄と再生成を deny する（[D-015](../../decisions.md#d-015)）。**上書きしない**
- 学習の run: **`runs/v4`**（`runs/v3` は M-49 などの再現用にそのまま残す）

## 6. 受け入れゲート

**すべてに陽性対照を付ける。** 陽性対照が落ちることを確認するまで、そのゲートは
「空虚に通っている」ものとして扱う。

⚠️ **どれが新規 clone で走るかを分けて書く。** コーパス本文（`data/splits/corpus_*.tsv`）も
ラベルパックも**リポジトリに入っていない**ので、実物を見る検査は CI では回らない。

| # | 検査 | 陽性対照 | CI |
|---|---|---|---|
| **G-L1a** | **allowlist の判定ロジック** — 合成した行で、(a) allowlist 外（`jsut/basic5000`）が拒否される / (b) **未知の `source`（`unknown/xxx`）も拒否される** / (c) 許可された 4 系統は通る | 判定表から 1 系統を抜くと該当ケースが落ちる | ✅ **入れる**（依存ゼロ） |
| **G-L1b** | **実際のパック**の `index.jsonl` に allowlist 外の `source` が **0 件** | `jsut/basic5000` の行を 1 件混ぜたパックで**必ず落ちる** | ❌ パックが要る |
| **G-L2** | **held-out が 1 行も変わっていない** — `corpus_heldout.tsv` の SHA-256 が凍結値と一致 | 1 文字変えると落ちる | ❌ 本文が要る |

⚠️ **G-L1a だけでは足りない。** 判定ロジックが正しくても、**それが実際に適用されたか**は
G-L1b でしか分からない（`gen_teacher_labels.py` が呼び忘れても G-L1a は通る）。
**B-1 の完了条件に G-L1b を含める。**

### 統計レポート（ゲートではない）

⚠️ **これはゲートと呼ばない。** しきい値を先に決められないので、**落ちることがない**。
ゲートの体裁で書くと「空虚に通るゲート」そのものになる。**出力を人が読んで §7 を判断する。**

**⚠️ レポート自身に陽性対照を付ける**（差を検出できることを示すため）:

- **陰性対照**: 同じ split を 2 回入れて、差が全項目 0 と報告されること
- **陽性対照**: v3 の split と CC0 split を入れて、**JSUT 固有の軸（助数詞 / カタカナ語 /
  オノマトペ / 法令文）に差が出ると報告されること**。差が出なければ**レポートが壊れている**

### レポートが見るもの

JSUT で失う軸は **525 行**:

| 軸 | subset | train 行数 |
|---|---|---:|
| 助数詞 | `jsut/countersuffix26` | 23 |
| カタカナ語 | `jsut/loanword128` | 115 |
| オノマトペ | `jsut/onomatopee300` | 270 |
| 法令文 | `jsut/precedent130` | 117 |

⚠️ **オノマトペ 270 行が品質に効いているかは誰も測っていない。**
「日本語固有の多様性軸だから要る」は仮定である。レポートは次を v3 と並べて出す:

- 音素のユニーク数と出現分布（`src/saanotts_jp/vocab.py` の 57 音素）
- 文字種の内訳（漢字 / ひらがな / カタカナ / 英数字 / 約物）
- 中間表現の長さ分布
- アクセント記号（`[` `]` `#`）と無声化マーク（`°`）の出現率

### ⚠️ ゲートが見ないもの

- **音**。聴取は G32 と同じく人が要る
- **品質**。落ちるかどうかは L2-B の B-3 でしか分からない
- **「軸が薄くなったこと」の影響**。カバレッジの差は品質の差ではない

## 7. 多様性軸の補充

**先に測る。測って落ちた軸だけ補う。**

補う場合の方式は**自作（MIT）**とする。`curated/question_eos` 39 行が前例で、
`source` に `curated/` を足すだけで allowlist に乗る。

⚠️ **CC0 素材からの抽出は当てにしない。** ROHAN4600 と ITA は音素バランスで
設計されているが、**助数詞・カタカナ語・オノマトペを軸として持っているわけではない。**
「既存素材で埋まる」は測るまで仮定である。
