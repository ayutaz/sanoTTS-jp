# ゲートを書く

## 原則

**「テストが通った」は「正しい」ではない。**
このプロジェクトで見つかった欠陥の多くは、**テストが緑のまま**潜んでいた。

ゲートを書いたら必ず自問する:

> **このゲートが落ちるような壊し方を、私は 1 つ言えるか。**
> **その壊し方を実際に入れて、落ちることを確認したか。**

言えないなら、それは**ゲートではなく printf** である。

## 実際に空虚だったゲート

| ゲート | 何を測っていたか | 発覚の仕方 |
|---|---|---|
| `golden_test` の「参照実装と一致」 | **Pearson だけ**。表示していた SNR は合否に入っていなかった。Pearson はスケールとオフセットに不変なので、**層を 1 つ落としても 0.98 を超える** | 敵対的検証 |
| `int8_e2e_test` の「fp32 比 25 dB」 | 2 つのブロブが**同じでも通る**。`./int8_e2e_test a.bin a.bin …` が「**平均 inf dB / OK**」 | 敵対的検証 |
| `stream_test` の G1「ピーク RAM < 200 KB」 | **arena の外にある FFT の stack 4,224 B を数えていなかった** | 照合 |
| `bench` のレイテンシ | 結果を使っていないので**コンパイラがループごと消して 0.000 ms** | 値が異常すぎて気づいた |
| ラベル生成の 13 ゲート | TSV の**ヘッダ行**が `uid="id"` / `text="text"` の発話として全部通った（C-018） | 出力の先頭を見て |
| **`sanitize_reports.py` の「合計 0 箇所」** | **本文検出が 3 つの穴で 36 箇所を見逃していた**（キー名の許可リスト / 走査範囲 / リスト直下の文字列）。**陽性対照が無かったので「0」が安全か無能か区別できなかった**。24 文を公開してしまった（C-028） | 別タスクの回帰点検 |
| `arena_stress` のゲート 1 | `saan_alloc` が失敗しても `used` を進めないので、**大きい確保だけ失敗して後続の小さい確保が成功**。`init` が `SAAN_OK` を返したまま NULL を抱える | 敵対的検証 |
| **K-7 の「Viterbi は 1 KB で足りる」** | `-DARENA_N=...` を渡して測ったが、**`.c` の中の `#define ARENA_N` が勝っていた**。どの値でも「全部一致」と出る。`#ifndef` にしたら**実際は 32 KB 要った** | 値が小さすぎて気づいた |
| **K-4b の「規則 1 は 4 回発火する」** | 発火はする。だが**書いた結果を後段の `njd_set_digit` が丸ごと上書きする**ので、出力を `"ズズズ"` に変えても 635/635 のまま通る。**「発火した」は「覆えている」ではない** | 注入で確かめて発覚 |
| **`check_doc_counters.py` の「件数が一致」** | README の主張を `\*\*(\d+) 件\*\*` で探したが、README は**太字なしの `6 件`** と書いてあった。**一致 0 件のまま「OK」と出た**。`\*{0,2}` にして **「一致 0 件は NG」を足したら、実体 10 件に対し 6 件**だった | 書いた直後に実ファイルを目で見て |
| **`int8_test` の W8A8 SNR（M-58 以降）** | `qx` を `cin·T` で確保していたが、カーネルは `align16(cin)·T` 書く。**隣のヒープに溢れたまま 5 日間「OK」**。S4 で確保の順番が変わり `nan` で表面化（C-053） | 別の変更で nan が出て |
| **K-6 の「Sudachi の影響 0 / 600」** | `phonemize()` が `lru_cache` を通るので、**1 回目に固まった値が返り続けていた**。**陽性対照ごと 0** だった。`cache_clear()` を挟んだら 12 / 600 | 陽性対照を足して発覚 |

### この 4 つに共通する形

**「小さい / 0 という結果が出たら、まず測定器を疑う。」**

| 形 | 確かめ方 |
|---|---|
| `-D` で定数を差し替えて測った | **`#define` が勝っていないか。** `#ifndef` で囲ってあるか |
| 「N 回実行したが差が出ない」 | **キャッシュを挟んでいないか。** 陽性対照（必ず変わるはずの操作）で先に確かめる |
| 「この段は発火している」 | **発火は覆えている証拠ではない。** 出力を壊して落ちるか見る |
| カーネルの契約（書く量・読む量）を変えた | **その関数を直接呼ぶテストの確保量を grep する。** arena 経由は `saan_act_scratch_needed` が数えるが、直接呼ぶテストは手で確保している（C-053） |
| 正規表現・パターンで実ファイルを検査した | **何件一致したかを出せ。** 0 件一致は「合格」ではなく「効いていない」。**実ファイルを 1 つわざと壊して落ちるか見る** |

## 書くときのチェック

### 1. 不変量を持つ指標を単独で合否にしない

**Pearson・相関・コサイン類似度はスケールとオフセットに不変。**
「形が合っている」しか言えないので、**必ず SNR や max|Δ| と併記して両方を合否に入れる**。

```c
/* ✗ 形しか見ていない */
const int ok = c.pearson >= 0.98;

/* ✓ */
const int ok = c.pearson >= 0.98 && c.snr_db >= 40.0;
```

同じ理由で **CER・一致率も単独では弱い**（C-023 で表記 CER と かな CER が逆の符号を出した）。

### 2. 「2 つを比べる」ゲートは**2 つが違うことを検査**する

同じものを 2 回渡したときに `inf dB` で通るゲートは、**引数を取り違えても気づけない**。

```c
/* 比較の前に、比較対象が本当に別物かを確かめる */
if (dtf != 0u) { fprintf(stderr, "NG! 第1引数は fp32 でなければならない\n"); return 1; }
if (dti != 1u) { fprintf(stderr, "NG! 第2引数は int8 でなければならない\n"); return 1; }
if (fsz == isz && memcmp(fb, ib, fsz) == 0) { fprintf(stderr, "NG! 同一ブロブ\n"); return 1; }
```

### 「0 件」を報告するゲートには、必ず陽性対照を同居させる

**「0 件でした」は「安全」ではない。「検出できなかった」かもしれない。**
両者を区別する手段が無いゲートは、**無いより悪い**（安全だと誤解させるから）。

```python
# ✗ これだけでは、検出器が壊れていても 0 が出る
print(f"合計 {total} 箇所")

# ✓ 検出できることを先に示す
assert detect(known_positive) == 1, "陽性対照が捕まらない = 検出器が壊れている"
print(f"合計 {total} 箇所")
```

⚠️ **走査範囲・キー名・型で対象を絞るゲートは、絞った外側を必ず取りこぼす。**
`sanitize_reports.py` は 3 つ同時に絞っていた（キー名の許可リスト /
`--root reports` / dict の値だけ）。**絞るたびに、絞った外側の陽性対照を足すこと。**

⚠️ **厳しくする修正が別の破壊を生む。** 上の修正でキー名判定を外した直後、
単独モーラ `し` がコーパス行と一致して**無関係な評価データを伏せかけた**。
**陰性対照（巻き込んではいけないもの）も同時に張る。**

**陽性対照を入れるのが最も強い。** B-12 の重複検査は
「MOE の行 200 件をそのまま query に入れると 200/200 が一致する」を
**スクリプト内で assert** している。これがあると「0 件」が検出漏れでないと言える。

### 3. 資源の予算は「確保しているもの全部」を数える

`arena` だけ数えて **stack を数えない**と 200 KB を割ったように見える。
ESP32 では**同じ SRAM を食う**ので嘘になる。

- 関数の自動変数は `otool -tv` / `objdump -d` で**実フレームを読む**
  （⚠️ `sub sp, sp, #0x1000` の**あとにもう 1 つ `sub` がある**ことがある。4,096 ではなく 4,224 だった）
- 一時確保を巻き戻す設計なら、`used` ではなく**高水位 `peak`** を見る

### 4. 失敗を粘着させる

「失敗しても状態を進めない」アロケータは、**後続の小さい確保が成功してしまう**。
呼び出し側が最後の 1 個しか NULL 検査していないと、**初期化が成功を返したまま NULL を抱える**。

```c
if (a->failed) return NULL;                        /* 一度失敗したら以降すべて NULL */
if (a->used + need > a->size) { a->failed = 1; return NULL; }
```

**呼び出し側で全部検査する**のは抜けやすい。**1 箇所（アロケータ側）で守る。**

### 5. ベンチは結果を使う

```c
/* ✗ 消える */  for (int i=0;i<N;++i) f(x);
/* ✓ */        volatile double sink = 0; for (int i=0;i<N;++i) sink += f(x);
```

**0.000 ms が出たら測れていない**と考える。

### 6. しきい値の出どころを書く

**実測値に合わせて後から決めたしきい値は、回帰検出には使えるが合格基準ではない。**
そう書く。

```c
/* ⚠️ M-45 の実測に合わせてある。回帰検出用であって独立な合格基準ではない */
#define GATE_MIN_DB 23.0     /* 観測最小 23.27 dB（余裕 0.27 dB） */
```

⚠️ **依頼されたゲートを勝手に緩めない。**
「SNR ≥ 25 dB」と指定されたなら、**満たさなかったときは「満たさなかった」と報告する**。
判定式を「平均 ≥ 25 かつ最小 ≥ 23」に書き換えて OK を出すのは、**報告ではなく偽装**。

### 7. ゲートは値の異常を捕まえる。行が実データでないことは捕まえられない

13 個のゲートを持つラベル生成器で、**TSV のヘッダ行**が発話として通った（C-018）。
「テキスト」は日本語として読めるので、長さも速度も音量も全部正常だった。

- **入力の読み込み側でしか防げない**（`skip_header` を書く）
- **出力の先頭 1 件を必ず目で見る**（`seq=0` を見れば一発で分かった）

### 8. 陰性対照は「壊す対象が測定対象に入っているか」まで確かめる

**規模を変えたら陰性対照が黙って無力化する**ことがある。K-1 / K-2 で 2 回踏んだ。

| 何をした | どうなったか |
|---|---|
| trie の「辿ったノード」から 1 個選んで壊した | **ヒットを 1 件も生まない経路**のノードだった。参照側も空なので一致してしまい、**不一致 0 件**で「通った」ように見えた |
| チェックポイントの 1 番を固定で壊した | 1 番が覆うのは**エントリ 32..63 だけ**。789,388 件から 20,000 件を抽くとそこに 1 件も当たらず、**不一致 0 件**になった |

どちらも **370,863 entries では偶然 1〜3 件出ていた**のが、789,388 にしたら 0 になった。
**「前は落ちていた」は根拠にならない。**

**3 つ目の形: 分母が失敗ケースを除外する。** K-3 で踏んだ。

```c
if (m != expected) { ng++; continue; }   /* ← ここで抜けると */
if (has_unknown) { n_case++; ... }       /* ← 分母に入らない */
```

結果、**「未知語を含む文 53/53 通過」と表示しながら、実際は 59 件中 6 件落ちていた**。
**分母は判定より先に数えること。**

対策は 2 つとも同じ形:

- 壊す対象を**実際に効いた場所から選ぶ**（ヒットを生んだ終端ノード / 標本が入っているブロック）
- **「壊す対象が測定対象に入っている」ことを別のゲートで確かめる**
  （例: 『壊すブロックに標本が入っている』を OK/NG で出す）

```
NG  陰性対照: ずらすと落ちる    不一致 0 件      ← これは「通った」ではない
OK  壊すブロックに標本が入っている  ブロック 12623 に 1 件
OK  陰性対照: ずらすと落ちる    不一致 1 件
```

### 9. 注入して捕まらなかったら、**ゲートが弱いのか対象が効かないのか**を切り分ける

K-4 で 4 種類のバグを実装に注入した。3 つは捕まえたが 1 つは通った。

| 注入 | 結果 |
|---|---|
| retreat の符号を反転 | NG 538/600 → 捕まえた |
| マス形の 1/2 を入れ替え | NG 563/600 → 捕まえた |
| filler の `>` を `>=` に | NG 549/600 → 捕まえた |
| **4 段の順序を入れ替え** | **OK 600/600 → 捕まえない** |

ここで「ゲートが弱い」と決めつけるのは早い。**参照実装側で同じ入れ替えを測った**ところ、
held-out 1,200 文で **1 文も結果が変わらなかった**。つまり
**corpus がその性質を区別しないだけ**で、ゲートの欠陥ではなかった。

⚠️ **ただし、それは「順序は入れ替えてよい」という意味ではない。**
コードには「順序を入れ替えてはいけない」と書いてあったが、
**その主張はどこでも検証されていなかった。** コメントを訂正し、
ゲートの出力に「見ていないもの」として明記した。

**注入が捕まらなかったときにやること:**

1. 参照実装で同じ変更をして、出力が変わるか測る
2. 変わらないなら → **corpus が区別しない**。ゲートの限界として書く
3. 変わるなら → **ゲートが弱い**。区別できる入力を足す
4. どちらでも、**コードやドキュメントにその性質の主張が書いてあれば訂正する**

## 陽性対照は「実行して落ちるのを見た」ものだけを書く

**計画に書いた陽性対照が、実際には落ちないことがある。** S2 計画で 2 回踏んだ。

| 書いた陽性対照 | 実際 | 落ちる形 |
|---|---|---|
| **T1**: pull の終了条件を `< n_frames − 1` にすると末尾 1 フレームが欠ける | **落ちない。** 本番条件と等価だった（pull の境目は常に `emitted + ofill = 8m + 2`）。`− 8` に替えたが、再審査で **≡ 3, 4 (mod 8) を見逃す**と分かった（prefix 53 件で 40/53） | `− (CH+2)` = `− 10`（53/53） |
| **T5**: GELU のクランプを `3.9999f` にすると値が変わる | **落ちない。** `kSaanErfV[127]` も `[128]` も float で 1.0f なので **1 点も動かない** | `3.9f`（229,753 点が不一致） |

どちらも「壊し方としてもっともらしい」だけで、**測定対象に効いていなかった**
（上の「8. 陰性対照は『壊す対象が測定対象に入っているか』まで確かめる」と同じ形）。

**手順を固定する:**

1. 陽性対照を**先に実行して落ちるのを見る**。落ちなければ、それは陽性対照ではない
2. **どの入力で落ちたかを書く**（「53 件中 53 件」のように分母つきで）。
   一部でしか落ちないなら、**見逃す範囲を明記する**（`− 8` は ≡ 3, 4 を見逃す）
3. **計画・PR・notes に書く陽性対照は、実行済みのものだけ。**
   「こう壊せば落ちるはず」は仮説であって、ゲートの根拠にならない

⚠️ **`3.9999f` のような「境界のすぐ内側」は、表の値が飽和していると 1 点も動かない。**
連続量を壊すときは、**壊した結果が何点変わったかを数える**（0 点なら陽性対照は無効）。

## 落ちることを確認する

新しいゲートを足したら、**壊して落ちることを 1 回見る**。

```bash
# 例: 同一ブロブを渡して弾かれるか
./int8_e2e_test student.bin student.bin golden.bin ids_heldout.bin /dev/null   # NG! が出ること

# 例: hook の回帰は allow と deny を両方持つ
uv run python .claude/hooks/test_guard_bash.py     # 94/94 + commit ガード 6 件
```

⚠️ **`allow` 側のケースを必ず入れる。** deny だけのテストは
「全部 deny にする」実装で満点を取れてしまう。hook の誤検知は**5 回踏んでいる**。

## all-test に入れる

**手で走らせるゲートは、いずれ走らせなくなる。**

`make -C csrc all-test` に入っていない検査は「無い」と同じ。
既知の欠陥で落ちるから外している場合は、**外している理由と復帰条件を Makefile に書く**。
欠陥が直ったら**戻す**（`arena` は実際にこれで戻した）。

## 報告するとき

- **通ったゲートの名前ではなく、「何を見ていないか」を書く**
- しきい値が実測合わせなら**そう書く**
- 満たせなかったゲートは**満たせなかったと書く**（`not_done` に分ける）
